# V2.3 实际适配及未达成目标

冻结协议不追改；这里是看完本轮数据之后的事实解释。

- 实际是“相同强初始模型诊断之上的探测/更新策略”对照，而非三套完整端到端诊断程序。原始证据相同，还共享了一次模型产生的完整初诊；初诊10/10已定位精确模块。该适配减少模型差异，也使定位比较与共享修复接近天花板。
- Active的竞争解释在七项工具上的预测都没有形成不相交区间，因此正式任务0次探测。不能用17个构造器指定目标的校准探测，冒充正式M选择的主动实验；不能称实际验证了主动区分竞争解释的科研机制。
- Fixed确实执行20次探测，其中19次有数值读数；对同一预测的多个解释，更新器全部写unresolved。其0/10最终精确模块命中不是10次错误诊断；初始模块命中同样10/10，编码器也能读到。Active/Fixed实际两次探测匹配子集n=0，只匹配了预算上限。
- 编码提示没有逐函数告知正确实现，也没有注入补丁或隐藏标签。但完整源码和公共三维SceneAct参数仍让错误容易静态识别。三组均10/10有效修复和迁移，未证明主动诊断带来下游研发优势。
- H是实际SceneAct编译器及少量编辑/支撑接口；P为确定性参数化家具场景；不是自然图像完整重建H的再演化。两个模板、10个注入配置不等于10个独立自然房间；transfer是另一模板/参数/部件组合的程序功能验证。
- geometry/position replay检查公共家具角色输入的整计划契约，不是任意视觉对象上的几何归因。局部四类操作按M提供的真实对象ID执行；未知目标不能自动猜第一个Mesh。
- 固定9项结构/编辑门槛覆盖本轮box场景，未覆盖全部SceneAct原语/Boolean接口。机械编辑不等于文字指令编辑，AABB接触不等于Mesh碰撞；无自然图像三维真值。
- M为工程实现，正式期间未修改。没有自动后代或冻结陌生H回放；没有证据支持元能力提升，也不能宣称胜过SceneEvolve或Hyperagents。
- 原runner字段 `changed_module_count` 实为函数文本变化数，格式重排会放大。原记录未改；`metrics/code_scope.csv`补充语法结构变化，仍不能用计数判断语义过修复。真实回归以固定功能检测为准。

本轮数据可以支持工具可执行性、固定功能测试灵敏性和共享编译程序修复的可迁移可行性；**目前不能支持论文贡献一的主动诊断研发优势**。需要真正含可执行辨识实验的竞争故障，以及降低强初诊天花板的公平设计后，再在独立任务上验证。该工作本轮未追加启动。

后续元级入口：本轮公开接口是 `experiments/scene_rsi_v2_3/meta.py` 的 `plan_probes(context)` 与 `plan_patch(context, observations)`。历史 `experiments/scene_rsi_pilot/replay.py` 仅作V1参考，不直接兼容V2.3辅助H。本轮尚无可比较自动M后代，因而没有提供伪装成可运行MetaImp的空入口。新阶段必须先获得真实使用过的M后代，另冻陌生H起点、新任务和相同显式记忆，再独立编排提案与Selection/Test；不能再把这十个公开任务当新盲测。
