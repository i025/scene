# 阶段式教学与学生自检查：运行前协议

本协议在正式 D01/T01 模型调用之前保存；模型联通烟测单独计入准备预算。它是一条在线教学与语言策略迁移案例，不是权重训练、教师自进化、A/B质量比较或普遍能力证明。

## 数据与共同起点

- D01：完整办公室，Commons 来源 186238614，上一教师实验 D02。环境、桌椅、柜体、植物等可辨，适合逐步建模。
- T01：Robie House 厨房，Commons 来源 70764945，上一教师实验 E02。另一来源与布局，不是开发图的裁剪或同室视角。
- 两者均已历史曝光；这次只保证 T01 不进入开发教师和提炼调用，不宣称从未曝光的盲测。来源路径、历史、CC 许可和归属见 manifest.json。
- 两任务各初始化空场景一次，互相隔离。复用上轮 backend/SceneAct 与 Blender 4.2.10，代码来源 e85adef03cab8333d817610820a3e7d5a431957c。旧实验与已演化教师源码不改变。

## 模型和语言

- 学生建模、技术修复、T01 自查及复核：gpt-6.1-terra / medium。
- D01 在线教师与一次轨迹提炼：gpt-6-astra / medium。
- Codex CLI 0.163.0，现有登录与薄适配器；所有提示、模型生成文本、提炼规则和代码注释用英文。中文仅用于向用户展示的说明/人工译述，不回流模型上下文。
- 模型请求名与实际可观测路由分开；没有独立返回字段时 observed_model=unknown。没有货币账单，不宣称降本。
- 每次 exec 新临时会话，真实图像附件；只提供本次必要显式上下文和图像。read-only，禁 shell/MCP/web/subagent/file 工具，关闭项目文档与隐藏历史加载；不改全局账号或安全设置。出现可见内层工具即暂停并计费。底层精确请求数未知，不以 exec 数冒充。

## 阶段与持续检查点

学生在各图第一次调用中自行制定 4–5 阶段计划，随后冻结。环境/相机/基础照明先行，后续按实际场景的主体、次要关系、外观和整体回看组织；教师在第一次构建之后才开始。

每个阶段执行：学生增量补丁 → 构建保存 → 真实预览 → 教师（开发）或同一学生（测试）看图 → 至多一次视觉补丁 → 真实预览 → 至多一次复核。允许没有问题而直接前进，未解决问题继续保留。

每阶段额外技术修复最多一次，由初始补丁和视觉补丁共同使用。技术修复后仍需真实看图反馈；没有有效阶段图则 visual_loop_incomplete，不声称完成。失败增量补丁不覆盖父检查点，保存代码与异常；明确记录保留父场景，不按隐藏质量分选择。

后续补丁加载上一 .blend，使用 bpy 编辑或 SceneAct realize(new_scene, clear=False) 追加。禁止清空、重新完整构造、外部文件/网络、模型自行执行 Blender、保存/渲染、修改质量或资源。固定入口保存对象 ID、对象/材质/父子关系、相机前后变化；原始坐标与材质参数直接比较，不使用内容哈希。结构记录是技术事实，不能证明真实三维恢复准确。

教师只评价当前阶段已完成范围及其依赖，最多三项自然语言意见，不写代码，不处罚未来阶段未创建物体。学生逐项记录实现/部分实现/未实现/不适用，下一真实图像检验这些自述。复核仍要求修改时，转为 advance_with_issue 并停止该阶段纠错，不追加机会。

## 提炼与测试隔离

D01 完成后一次 Astra 提炼，最多一次格式/接口/来源修正。只输入 D01 教学轨迹、真实结果和固定接口，不提供 T01 的图像、内容或任何历史答案。

生成 self_check_policy.md（5–8条）、student_self_review.py 的 build_review_prompt(context) 纯函数和 lesson_provenance.json。每条开发派生规则引用实际阶段和反馈 ID，区分原有通用规则、开发派生规则、未迁移意见和限制。不允许搬运单图构造答案。

首次 T01 调用前冻结代码和规则。测试只拿通用策略、当前测试原图、当前检查点与有界操作记录；不拿开发 provenance、图像、代码、完整教师对话。固定入口每次实际调用提炼函数构造自查提示，再由 Terra 查看当前真实附件并做决定。测试发现必须 problem_source=test_observation，规则来源为冻结 ID 或 student_prior_judgment；不得把旧意见改写成新发现。测试任何 Astra 或教师调用都是协议错误。

## 预算与资源

整轮硬上限：CLI60，开发含提炼30、测试28、准备2；构建36；渲染尝试80。两张图是两个完整任务，检查点不是独立样本。服务重试及失败均计入。同一调用只有已知瞬时服务错误允许一次重试；路由/额度/代理故障先暂停，不批量提交其他任务。模型超时不自动重抽。

五阶段最坏正常流程估算：开发计划1+五阶段×(建模1+教师1+视觉补丁1+复核1+技术修复1)+提炼2=28；测试计划1+五阶段×5=26；准备2，共56。剩余分区额度用于有限服务重试。最多30正式构建，加预备3次共33，低于36；正式最多30预览+2交付，加烟测2帧为34，低于80。阶段选择4时实际额度更低，预算不要求用满。

CPU沿用已有明确授权8核、32GB，没有调度器授予16核证据；从实际 affinity 选8个CPU，不把整机256核当授权。单Blender进程×8线程；无GPU。数值库与CLI辅助线程统一配置，CLI辅助1线程，无重任务并行。

预览长边768、Cycles16samples；最终交付长边1024、32samples，原图比例；AgX、seed42、CPU，完整设置见config。最终高质量图只改变分辨率/采样，不改变场景，不额外调用模型评审。低分辨率微型夹具排除正式结果。

单CLI900秒、构建1200秒、渲染600秒，每图活动墙钟5400秒；执行串行，剩余时限约束每次提交，预留90秒不再请求新代码。远端等待计入CLI墙钟，不伪造纯推理时间。中断外等待不计活动预算，恢复保留累计执行时间。32GB进程树上限；记录GNU time CPU user/system与RSS，采样峰值是下界。

## 验证、终态与交付

正式前只用微型确定性夹具检验增量加载、ID保持、失败父场景不覆盖、重新打开与渲染，并用两个指定模型检查真实图片附件；全部计入总预算，不引入第三张正式图。

关闭BW、Q、SSIM、LPIPS、DINO、VLM judge和自动质量排名。教师意见、学生发现及复核都是机制内观察，可能错误，不是真值；无人类预填判定。

保存原图、计划、每次补丁/失败/检查点、英文原始调用、阶段事件、实际输入附件、规则来源、冻结快照、CSV、中文离线HTML及报告。resume只补未完成步骤，复用已保存响应，不重抽终态失败、不创建第三任务或新教师版本。running只用于实际运行进程；进程中断需核对真实阶段，不直接重启成功步骤。

公开包保留这两张允许再分发的CC原图及归属，保留原有第三方许可。代码/核心CSV/图入新分支，大日志/.blend入新Release。未脱敏原日志留服务器，公开路径前缀脱敏；不上传凭证、模型、缓存，不做哈希验证。
