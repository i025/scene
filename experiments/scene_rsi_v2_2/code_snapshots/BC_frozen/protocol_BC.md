# V2.2 B/C 协议（须确定性验收后由 BC_freeze.json 冻结）

本轮没有多代 RSI 搜索，没有新的自动 M 后代。V2.1 M0 为冻结对照；V2.2 M 是工程师编写的诊断机制修复。

## 对象与数据

- 10 个新的参数化 SceneAct 房间故障任务：5 类×2 个场景配置，来自两种家具模板。它们不是 10 个自然场景或独立物理采集样本。
- 焦距；家具尺度；对象隐藏；支撑坐标/部件脱离；共享材质的非目标变化。
- 夹具构造时保存真实故障、主要对象及允许模块集合；先于任何诊断调用。真值和正确 helper 源码只供评价器，绝不放进 CLI 提示或附件。
- 被测 M 看到相同原图、故障渲染、真实对象/投影和公共程序。一个共同 astra 视觉定位调用生成含竞争解释与事前方向预测的证据，原样给双方。
- 参考 helper 的 API 契约为双方共同提供强提示，编码器也能独立发现明显代码缺陷。对此形成修复天花板的风险明确报告。

## 决策与执行

每组每任务都采用同一两阶段接口：plan_probes(context) → 真 Blender 探测/回归 → plan_patch(context,observations)。
明确输入剩余额度、已执行数、菜单、对象 ID、图像、指标和执行阶段。没有 blend 的失败只分析真实日志，不强行几何探测。

共同菜单：camera_focal、object_scale、isolate；每组每任务最多2次。相机固定几何改变焦距×1.1；对象尺度固定相机绕真实几何包围盒中心×1.1；隔离隐藏其他 Mesh，不会取消目标 hide_render。
探测只修改临时内存场景并保存真实 probe_scene.blend；数值图像评分的可打开验证也使用该探测副本，不用原始场景冒充探测后的工程。原提交保持不变。
每个探测最多600秒。CPU Cycles、16 samples、256×192、seed42、AgX；此为单独冻结的控制场景协议，双方与参考一致。非正式目标测试可64×64/1 sample并单独标注排除。

共同研发回归菜单沿用6项，每组最多3项，M实际选择并执行。material_preservation 在C适配为调用当前共享 helper 的 local_material，并比较真实非目标几何/材质；其余复用固定 Blender 检查。它不同于A预定义安全蓝色操作，不能混称文字编辑。
所有最终 helper 测试固定，不允许 M 关闭：焦距、尺度、可见性、支撑/声明层级、材质非目标保持、组合移动的部件跟随。

V2.2 对隔离只使用真实可见性、成员关系等事实，不用全图Q变好证明遗漏。其他敏感性测量按事前预测方向比较，Q增量容差±0.005；相同方向或未知预测不能证明区分。支持也只相对于所提候选解释，不声称唯一原因。
V2.1 M0源码不修改。双方得到完全相同的公共视觉证据、菜单、探测上限和回归上限；策略可不同地使用它们。

## 共享程序修复与迁移

每组每任务相同一个受损共享 helper H，1次 gpt-6-astra medium 编码调用，最多600秒，无模型修复重试。
任一组都允许编码器修复任意 helper 函数，包括 M 定位错误或 unresolved 时；不人为用模块门禁削弱对照。
源场景与迁移场景在同一次、最多600秒的 Blender 执行中构建和各渲染1帧。迁移改变参数、家具尺寸、相机距离、对象名和共享 Mesh/材质所有权。
仅修改该 helper；禁止 task_id、图片路径、对象特例表；保存源码、diff、实际执行与所有失败。
此 H 是控制夹具的共享变换程序，不是实验A的自然图像 H0/r1-C2；迁移通过不等于自然图像算法收益。
修改后旧定位只作历史证据，当前库存与固定回归重新测量；本轮不新增修改后视觉定位，明确记录没有当前定位，不能沿用旧映射为事实。

## 评价与成本

- 对象top1命中：主要对象的预先定义等价表示；相机2例对象 N/A。其他受影响对象另保留原始变更数据，不事后扩大主答案集合。
- 初始模块top1/any、第二阶段最终模块分别计数，unknown/unresolved 不算模块命中。
- 精确模块与宽泛相关模块分开：support/part dependency 可相关于旧M的 structure_and_edit_contract，material 可相关于该旧标签，coverage 可相关于旧 object_coverage_and_verification。相关集合在造夹具时写入真值，不在结果后扩大；不能只按新M的标签词汇宣称优势。
- 事前预测的方向区分性：有实际控制观测且仅一个已记录预测方向匹配；隔离排除全图Q。该代理不是真实因果证明。
- 同一个固定M在相同context下分别接收实际观测与空观测，保存最终模块是否改变；这是零模型调用的程序依赖检查，不是冻结M代际能力回放，空观测输出不提供给编码器。
- 实测源修复、独立 helper 迁移、失败零效用分别报告，缺测原始布尔/图像指标null，所有20个预定臂保留。
- common视觉调用10次实际只计一次；每组看到10次相同证据。成本可各分摊一半，不能把总10次写成20次。编码最多20次，总C最多30次CLI。
- 共同建场20帧；每组最多20个探测帧与20个修复帧，C最多100帧。全部计入整轮180 CLI/600帧上限，不为正结果追加预算。
- CLI内层重连不是独立会话；usage缺失unknown/null，实际模型路由未报告unknown。所有调用使用已有CLI，禁止网页/隐藏子代理/第三模型。

## 案例和结论

图按全部预定任务展示。案例板选择冻结顺序第一个V2.2最终模块正确且实测修复成功的案例，再选择任一组第一个真实模块错误或修复失败。模块失败而编码器修复成功时必须明确区分。

CLI服务细化规则属于运行中的as-run修订，见configs/SERVICE_AS_RUN_AMENDMENT.md。原有失败不重采样；最多3次不同事件恢复检查，失败即停止新调用。
